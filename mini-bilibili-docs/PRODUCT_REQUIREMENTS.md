# MiniBili 视频社区平台产品需求文档

版本：V1.0（学习项目 MVP）  
产品定位：面向动漫、游戏、音乐、绘画等兴趣创作者的轻量视频社区。  
项目目标：用一个完整、可演示的前后端分离项目，练习 Spring Boot、MyBatis、MySQL、动态 SQL、前端联调和部署。

## 1. 目标与边界

MiniBili 不追求真实视频网站的海量并发和完整转码系统。第一版重点证明你能：

- 设计并实现清晰的业务模型。
- 完成登录、发布、审核、检索和互动闭环。
- 用 MyBatis XML 编写复杂查询与动态 SQL。
- 完成前后端联调、异常处理、测试和部署。

第一版不做：直播、弹幕实时系统、付费会员、复杂推荐算法、视频多清晰度转码、微服务。

## 2. 用户角色

| 角色 | 核心目标 | 主要能力 |
|---|---|---|
| 游客 | 发现内容 | 浏览首页、搜索、查看视频和评论 |
| 注册用户 | 互动和收藏 | 登录、评论、点赞、收藏、关注 |
| 创作者 | 发布和管理作品 | 投稿、编辑、查看数据、处理评论 |
| 管理员 | 维护社区秩序 | 审核视频、处理举报、管理用户和分类 |

## 3. MVP 功能

### 3.1 首页与发现

- 顶部导航、搜索、分区入口。
- 推荐视频网格、热门话题、创作者计划。
- 按分类、关键词筛选。
- 支持最新、最热、点赞数排序。

### 3.2 视频

- 视频投稿：标题、简介、分类、标签、封面、视频文件。
- 投稿后进入“待审核”状态。
- 审核通过后可在首页和搜索中出现。
- 视频详情展示播放区、作者、简介、点赞、收藏、评论。

### 3.3 用户与创作者

- 注册、登录、退出。
- 个人资料和头像。
- 个人空间：作品、收藏、关注、粉丝。
- 创作中心：投稿状态、播放量、点赞数。

### 3.4 社区互动

- 视频点赞与取消点赞。
- 收藏与取消收藏。
- 关注与取消关注。
- 一级评论和二级回复。
- 数据库唯一索引防止重复点赞、收藏和关注。

### 3.5 管理后台

- 视频审核：待审核、通过、拒绝、下架。
- 用户管理：查询、禁用、恢复。
- 分类管理：新增、排序、启停。
- 简单统计：新增用户、投稿数、播放量。

## 4. 页面清单

| 页面 | 路由建议 | MVP |
|---|---|---|
| 首页 | `/` | 是 |
| 搜索结果 | `/search` | 是 |
| 视频播放 | `/video/:id` | 是 |
| 投稿 | `/studio/upload` | 是 |
| 创作中心 | `/studio` | 是 |
| 个人空间 | `/space/:userId` | 是 |
| 登录/注册 | `/login` | 是 |
| 动态广场 | `/feed` | 二期 |
| 管理后台 | `/admin` | 是 |

当前前端交付为可交互视觉原型，首页的导航、搜索、筛选、点赞、投稿提示均可操作。其余路由的完整业务页面建议随着后端模块逐个加入。

## 5. 核心业务流程

### 投稿审核

创作者投稿 → 校验字段和文件 → 保存视频记录（待审核）→ 管理员审核 → 通过后记录发布时间 → 出现在公开列表。

### 点赞

用户点击点赞 → 后端校验登录 → 插入点赞关系 → 更新视频点赞计数 → 返回最新状态。重复点赞由 `(user_id, video_id)` 唯一索引兜底。

### 评论

用户评论 → 内容校验 → 保存一级评论；回复评论时同时记录 `parent_id` 和 `root_id`，查询时先分页一级评论，再批量查询对应回复。

## 6. 数据模型

第一版核心表：

- `mb_user`：用户。
- `mb_category`：视频分类。
- `mb_video`：视频主体和统计字段。
- `mb_comment`：评论与回复。
- `mb_video_like`：点赞关系。
- `mb_favorite`：收藏关系。
- `mb_follow`：关注关系。

后续可加入 `mb_video_tag`、`mb_tag`、`mb_notification`、`mb_audit_log`。

## 7. 动态 SQL 练习设计

视频列表是本项目最重要的动态 SQL 场景，参数可任意组合：

| 参数 | 说明 |
|---|---|
| `keyword` | 标题或作者昵称模糊搜索 |
| `categoryId` | 分类 |
| `userId` | 指定创作者 |
| `minViews` | 最低播放量 |
| `status` | 审核状态 |
| `startTime/endTime` | 发布时间区间 |
| `sortBy` | `latest` / `hot` / `likes` |
| `page/pageSize` | 分页 |

已在后端 `VideoMapper.xml` 提供 `where`、`if`、`choose`、`include` 的完整示例。需要继续练习：

1. 使用 `foreach` 按多个分类或多个状态查询。
2. 管理后台按标题、作者、审核状态、日期组合筛选。
3. 使用 `set` 动态更新视频信息，避免空字段覆盖。
4. 批量下架视频。
5. 给组合查询运行 `EXPLAIN`，说明命中的索引。

注意：排序字段不可直接接受任意用户输入。应像示例一样通过 `choose` 映射到固定 SQL，避免 SQL 注入。

## 8. API 约定

统一前缀：`/api`。统一响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

核心接口建议：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/videos`
- `GET /api/videos/{id}`
- `POST /api/videos`
- `PUT /api/videos/{id}`
- `POST /api/videos/{id}/likes`
- `DELETE /api/videos/{id}/likes`
- `GET /api/videos/{id}/comments`
- `POST /api/videos/{id}/comments`
- `GET /api/admin/videos`
- `PATCH /api/admin/videos/{id}/audit`

## 9. 验收标准

- 首页在桌面和手机宽度下可用。
- 视频支持至少 5 个可组合筛选条件和 3 种安全排序。
- 未登录不能投稿、点赞或评论。
- 重复点赞、收藏、关注不会产生重复数据。
- 审核未通过的视频不会出现在公开列表。
- 查询不存在资源时返回明确业务错误。
- 核心接口至少覆盖正常、异常和权限测试。
- README 包含启动、数据库和演示说明。

## 10. 开发里程碑

| 周期 | 交付 |
|---|---|
| 第 1 周 | 数据库、公共结构、视频动态查询 |
| 第 2 周 | 注册登录、用户资料 |
| 第 3 周 | 投稿、视频详情、审核 |
| 第 4 周 | 点赞、收藏、关注 |
| 第 5 周 | 评论、个人空间、创作中心 |
| 第 6 周 | 测试、SQL 优化、联调与部署 |

每个里程碑完成后再进入下一个，不要同时铺开所有模块。
